# Shared CFD Transform — Native VTK Conversion Notes

This version removes the PyVista dependency and uses VTK's native Python wrappers directly.

## Main replacements

| Previous operation | Native VTK implementation |
|---|---|
| `pyvista.read(...)` | `vtkXMLGenericDataObjectReader`, `vtkGenericDataObjectReader`, `vtkHDFReader`, or `vtkOpenFOAMReader` |
| `MultiBlock` traversal | `vtkCompositeDataIterator` |
| dataset deep copy | `NewInstance()` + `DeepCopy()` |
| implicit-to-explicit coordinates | `vtkAppendFilter` → `vtkUnstructuredGrid` |
| NumPy ↔ VTK arrays | `vtk.util.numpy_support.vtk_to_numpy` / `numpy_to_vtk` |
| point → cell harmonization | `vtkPointDataToCellData` |
| cell → point harmonization | `vtkCellDataToPointData` |
| canonical-grid sampling | `vtkProbeFilter` with `vtkStaticCellLocator` prototype |
| valid sampling mask | `vtkValidPointMask` generated by `vtkProbeFilter` |

## Preserved contracts

The following behavior remains unchanged:

- canonical cell-centered physical grid;
- internal tensor order `[C, Z, Y, X]`;
- explicit field association and unit contracts;
- region conflict policies;
- frozen train-only normalization;
- channel-specific padding;
- masks, tensor hashes, and provenance metadata;
- inverse normalization and unpadding of predictions.

## Reader behavior

Supported inputs include common VTK family files such as `.vtk`, `.vtu`, `.vtp`, `.vti`, `.vtr`, `.vts`, `.vtm`, supported parallel XML variants, VTKHDF when available, and `.foam` marker files when the VTK build includes `vtkOpenFOAMReader`.

`.pvd` collections are intentionally rejected. Resolve a concrete time step before invoking the deterministic shared transform.

## Validation status

The script has been Python syntax-checked and statically checked to ensure there is no PyVista import or `pv.*` call. Runtime validation against actual CFD files still requires an environment with the `vtk` Python wheel and representative flow/TRD VTK data.
